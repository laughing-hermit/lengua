# x86-64 reference

What a program calls, the operations and the library functions, is in [the edge](edge.md). This
page is what is x86-64's: the registers an operation takes, how `main` starts, the calling
convention and the dialect's forms.

## Calling an operation

An operation's arguments go in `rdi`, `rsi`, `rdx`, `r10`, `r8` and `r9` (`r10`, not `rcx`), a
32-bit argument such as a descriptor in the low half (`edi`), and its result comes back in `rax`.
It changes `rax`, `rcx`, `r11`, the flags, every vector register and the mask registers `k0` to
`k7`, and no other register: a counter in `rbx` or a pointer in `rsi` is as it was after the call.
A result below zero is an error, so test it right away with `test rax, rax` and `js`:

```
    mov edi, STDOUT
    lea rsi, [rip + greeting]
    mov edx, GREETING_LEN
    call os_write
    test rax, rax
    js .Lmain_write_failed
```

`rcx`, `r11`, the vector registers and the mask registers can't be read after the call until
something sets them. The library's functions (`fill`, `assert_fail`, `parallel_for`) take their
arguments by the calling convention below, `rcx` fourth.

## Program start

lengua's `_start` calls `main`, so `main` is entered as a function is: `rdi` holds `argc`, the
number of arguments including the program's path; `rsi` the address of an array of pointers to
them, `argv[0]` the program's path, ending in 0; and `rdx` the address of an array of pointers to
the environment, each variable's `NAME=value`, ending in 0. Each is a NUL-terminated string,
read-only. `rsp` is 8 bytes off a multiple of 16, the return address: `sub rsp, 8` (or a push)
before the first call, as in any function. A program gets environment variables only when its idea
uses `the environment`, and then only those its test or the user's run gives; otherwise the list
is empty. lengua runs programs in a working folder of their own: an empty temporary folder, or the
user's folder when they ask to run the program on their files. `main` has nothing to return to: it
ends with `call os_exit`.

## Calling convention (System V)

- Arguments go in `rdi`, `rsi`, `rdx`, `rcx`, `r8` and `r9`; results come back in `rax`, and in
  `rdx` for a second value.
- A function must give back `rbx`, `rbp`, `r12` to `r15` (and `rsp`) unchanged; it may change
  `rax`, `rcx`, `rdx`, `rsi`, `rdi` and `r8` to `r11`.
- `rsp` is a multiple of 16 at every `call`, so a function starts 8 bytes off (the return
  address).

## Integer facts

- Writing a 32-bit register clears the upper half: `mov eax, 1` sets `rax` to 1, and
  `xor eax, eax` clears `rax`. Writing 8 or 16 bits leaves the rest unchanged, so load bytes with
  `movzx`.
- Signed division: `cqo`, then `idiv` (quotient in `rax`, remainder in `rdx`, truncated toward
  zero). Dividing by zero, or the most negative number by -1, kills the program with SIGFPE.
- Unsigned division: `xor edx, edx`, then `div`.
- `jo` catches signed overflow after `add`, `sub`, `imul` and `neg`; `jc` catches unsigned carry.
- Signed comparisons jump with `jl`, `jle`, `jg` and `jge`; unsigned ones with `jb`, `jbe`, `ja` and
  `jae`. Bounds checks use the unsigned ones, which also catch negative indexes.
- `imul rax, rbx, 10` multiplies by a constant. Characters are numbers: `sub eax, '0'` turns a
  digit's character into its value.
- Exit codes go from 0 to 255; 134 is lengua's code for a failed assertion.

## The baseline

The baseline is what every x86-64 machine lengua is written for has: SSE2, SSE3, SSSE3, SSE4.1,
SSE4.2 (with its `crc32`) and POPCNT, so `pcmpeqb`, `pmovmskb`, `pshufb`, `pminud`, `pcmpgtq`,
`popcnt` and `crc32` are all in it. Write for it first. Everything else the `machine` line lists
is an extension: BMI1 and BMI2 (`andn`, `tzcnt`, `bzhi`, `shrx`), LZCNT, ADX, MOVBE, AVX, AVX2,
FMA, AVX-512, AES-NI, SHA, PCLMULQDQ, VAES and GFNI. A program that needs one is a fast tier: a
program of its own, named for the extension, beside the baseline form and from the very same
idea, which you start from only where `machine` lists the extension. `check` refuses an
instruction the machine lacks (`needs BMI2, which this CPU doesn't have`), and lengua's own
programs are held to the baseline by `tests/baseline.rs`.

## Vector facts

- Every x86-64 CPU has SSE2: 16 `xmm` registers of 16 bytes, and the baseline adds SSE3 to
  SSE4.2. AVX2 adds 32-byte `ymm` forms (`vpaddb ymm0, ymm1, ymm2`) and AVX-512 64-byte `zmm`
  forms, 32 vector registers and the mask registers `k0` to `k7`; they are fast tiers, and a
  `check` reply's `machine` lists which this CPU has.
- No vector or mask register is callee-saved: after a `call` they hold anything, and an operation
  changes them all. A vector constant kept across a call is loaded again after it.
- Spread a byte over a register without data: `mov eax, 0x0a0a0a0a`, `movd xmm1, eax`,
  `pshufd xmm1, xmm1, 0`. With AVX2: `vpbroadcastb ymm1, xmm1`.
- Find bytes 16 at a time: `pcmpeqb xmm0, xmm1` sets each matching byte to `0xff`, `pmovmskb
  eax, xmm0` gathers one bit per byte, and `bsf` (or, with BMI1, `tzcnt`) gives the first match's
  index.
- Byte compares are signed (`pcmpgtb`): ASCII letters are below `0x80`, so they compare as
  expected.
- SSE instructions that read 16 bytes of memory need it aligned, except `movdqu` and `lddqu`; the
  `v` (VEX) forms don't. lengua allows only unaligned loads and stores.
- After using 256-bit or 512-bit registers, `vzeroupper` before SSE code avoids a slowdown on
  some CPUs.

### A baseline form, and faster tiers beside it

Every program has a baseline form that runs on every x86-64 computer: SSE2, `popcnt` and the
instructions that came with SSE3 to SSE4.2, and nothing else, so no `ymm` or `zmm`, no BMI
(`andn`, `bzhi`, `shrx`), no `k` masks. A faster form is a named tier beside it, picked from
the `machine` line of a `check` reply, and meets the very same idea.md, so the program's
behavior never depends on an optional extension:

| `machine` lists | Start the word count from |
|---|---|
| `avx512bw` | [`wc-avx512`](../assets/fast/wc-avx512/main.s), 64 bytes a step with `k` masks |
| otherwise | [`wc`](../assets/fast/wc/main.s), 16 bytes a step with SSE2 |

[The fast `wc`](../assets/fast/wc/main.s) is the baseline pattern for a loop over bytes. Without
`bzhi`, a masked last step is a vector of lanes: `movd xmm6, r8d` takes `min(left, 16)` (`cmova`
of the bytes left and a step), `pshufb xmm6, xmm10` (an all-zero vector) spreads it over the 16
lanes, `pminub xmm6, xmm9` takes the smaller of that and a vector of the lanes' places plus one,
1 to 16, and `pcmpeqb xmm6, xmm9` leaves all ones in the lanes where the place plus one was the
smaller, those that hold bytes before the end. Compare unsigned (`pminub`, `pcmpeqb`), not with
`pcmpgtb`: the proofs follow an unsigned compare of a byte to the length, and don't a signed
one. A compare's lanes are one bit each with `pmovmskb`, and `popcnt` adds them. Byte tests
without `vpcmpub`: `psubb` of the first byte, `psubusb` of
the range's width and `pcmpeqb` with zero find a byte in a range (tab to carriage return), and
`pcmpeqb` finds a single byte. A shift by an amount that depends on the input has no baseline
form the proofs follow, so find a bit of a mask with `bt reg, reg` instead (`bt r8w, r9w` takes
its bit number modulo 16).

## Floating-point facts

- Doubles travel in `xmm` registers: arguments in `xmm0` to `xmm7`, the result in `xmm0`. No
  `xmm` register is callee-saved.
- `cvtsi2sd xmm0, rax` turns a whole number into a double, exactly up to 2^53. `cvtsd2si rax,
  xmm0` rounds to the nearest whole number, ties to even; `cvttsd2si` rounds toward zero.
- After `ucomisd xmm0, xmm1`, jump with the unsigned conditions: `jb` (less), `ja` (greater),
  `je` (equal), and `jp` when either is NaN.
- Constants: `.double 100.0` in `.rodata`, read with `movsd xmm1, qword ptr [rip + hundred]`, or
  `mov eax, 100` and `cvtsi2sd xmm1, eax`.
- "12.34" is 1234 / 100.0: one `divsd` of two exact numbers gives the double the tests use.
- Singles work the same way with `ss` instructions: `cvtsi2ss` is exact up to 2^24, `.float 2.5`
  makes a constant, and `cvtss2sd` widens a single to a double exactly. The low 4 bytes of an
  `xmm` register hold a single.
- `vfmadd231sd xmm0, xmm1, xmm2` sets `xmm0 = xmm1 × xmm2 + xmm0` with one rounding; `132` and
  `213` choose other operand orders.
