# Review of the network a program chooses at run time (W18, first part)

This review was written with the design, before the code, by the author of both: it is not an
independent review. It lists what a program, or the computers it talks to, could try once an
idea may grant connections the program opens itself, the defence against each, and the test that
holds the defence. Paths are relative to the repository. The tests were written with the
defences, so none failed before its defence existed. To see them fail, one commit (20328da)
took the defences out and the next (ac6b05e) put them back: a rule covered every computer,
every spelling and every address was taken, a name was resolved again to connect, nothing
bounded or ended a program's connections, a UDP port answered any address, what came back after
a secret was sent wasn't secret, and the checker took lengua's own imports whatever the idea
granted. On Linux on x86-64 (run 43037211691) 17 of these tests failed on that commit: every
test named below but `each_address_has_its_class` and
`an_address_the_idea_writes_is_reached_as_written`, which test the classes and the rule's own
words, left as they were. The pool-level test hung on that commit for a fault of its own (it
dropped its module's file), so the run was cancelled after the library's tests; it is fixed.
Case 11's defence came after that run and wasn't shown failing.

## What changed

Before W18 a program opened nothing: lengua made the connections its idea named, before the
program started. Now an idea may also say, each on a `- Network:` line of its own:

| Line | Import of `lengua_net_1` |
|---|---|
| `opens TCP connections to port N on COMPUTERS [over TLS]` | `tcp_open` |
| `looks up the addresses of COMPUTERS` | `dns_lookup` |
| `sends UDP datagrams to port N on COMPUTERS` | `udp_open`, `udp_send`, `udp_recv` |
| `receives UDP datagrams on port N [for any computer]` | `udp_recv_from`, `udp_send_to` |

COMPUTERS is a name or an address, `any subdomain of example.com`, `the computer its first
argument names`, or `any computer`; `, private addresses too` at a line's end lets it reach
private networks.

The attacker is the program (the agent writes main.wat, and lengua treats it as untrusted),
steered by what it reads: a response, a redirect, a DNS answer, a datagram. The user saw the
idea's grants; the program must reach nothing past them.

## The order every call keeps

`src/wasm/host/open.rs` (`open_tcp`, `look_up`, `open_udp`) does these in this order, and
nothing is resolved or reached before step 2 passes:

1. `reach::spelled` reads the name: one spelling for each computer.
2. `Grants::granted` finds the rule of the idea that covers the name, the port, and TLS or not.
3. lengua resolves the name once; `reach::vetted` holds every address to the rule.
4. `reach::dial` connects to those addresses and no others; `reach::secure` does TLS and checks
   the certificate for the name.

## Threat cases

### 1. A computer the idea doesn't grant: a redirect, or anything else the program read

- Try: follow `Location: http://elsewhere.test/`; ask for `example.org` under a grant of its
  subdomains; ask for `www.example.org.evil.test`, or `badexample.org`; ask for the granted
  computer on another port, or in plain where the grant says TLS.
- Defence: `Rule::covers` (`src/reach.rs`): a named computer is that name alone; a subdomain
  rule needs a label, a dot, then the domain, and never covers an address; the port must be one
  of the rule's; `granted` takes TLS or not from the rule. Refused with `NOTCAPABLE` before
  anything is resolved.
- Tests: `reach::tests::a_rule_covers_its_computers_and_no_others`;
  `wasm::host::open::tests::what_no_rule_covers_is_refused_and_reported`; from the idea to done,
  `examples/follow`, behavior B3, where a test's server sends the program to `elsewhere.test`.
- What would fail: with `covers` always true, each "outside" name in the first test, and
  follow's B3, which would print the page.

### 2. This computer under another spelling

- Try: `localhost`, `LOCALHOST.`, `app.localhost`, `127.0.0.1`, `127.9.9.9`, `::1`, `0.0.0.0`,
  `::ffff:127.0.0.1`, `::ffff:7f00:1`; and the numbers an older parsing reads as addresses,
  `2130706433`, `127.1`, `0x7f.1`, `0177.0.0.1`, which the system's resolver would take.
- Defence: `spelled` refuses the first group as this computer (`NOTCAPABLE`) and the second as
  no name (`INVAL`), before the resolver sees them; it writes an IPv4 address inside an IPv6
  one as the IPv4 address, so a rule about one covers the other and a class is the address's
  own.
- Tests: `reach::tests::every_spelling_of_a_computer_is_one_spelling`; and, under a grant of
  any computer with a listener on the loopback's port, the spellings at the end of
  `open::tests::a_name_that_resolves_to_this_computer_or_a_private_network_is_not_reached`.
- What would fail: each spelling's assertion, and the listener would take a connection.

### 3. DNS tricks: a granted name that resolves where the grant doesn't reach

- Try: under `any computer`, or a domain the attacker's DNS answers for, a name that resolves to
  127.0.0.1, `::1`, 0.0.0.0, `::ffff:127.0.0.1`, to 10.0.0.1 or 169.254.169.254 (a cloud's
  credentials), or to a mix whose first address is public.
- Defence: `vetted` looks at every address the resolver gave. One that is this computer's
  refuses the name whole, whatever the grant; one in a private network does unless the rule
  says `, private addresses too` or writes that address; one of many computers does always.
  `class` reads the IPv4 address an IPv6 address carries: written inside it, IPv4-compatible,
  NAT64 (64:ff9b::/96), 6to4 (2002::/16).
- Tests: `reach::tests::a_name_is_reached_only_when_every_address_of_it_may_be`,
  `reach::tests::each_address_has_its_class`,
  `reach::tests::an_address_the_idea_writes_is_reached_as_written`; and
  `open::tests::a_name_that_resolves_to_this_computer_or_a_private_network_is_not_reached`,
  where a listener waits on the loopback and a resolver of the test's own gives each trick.
- What would fail: with `vetted` letting addresses through, the last test's listener takes a
  connection, and each name's `NOTCAPABLE` becomes a descriptor.

### 4. Rebinding: a name that resolves anew between the check and the connection

- Try: answer a public address to the check and 127.0.0.1 a moment later, to the connect.
- Defence: there is one resolution. `addresses_of` asks once, and `dial` takes addresses, not a
  name: the connection goes to what was checked. Over TLS the certificate is checked for the
  name besides.
- Test: `open::tests::a_name_is_resolved_once_and_only_its_checked_addresses_are_dialed`: the
  test's resolver counts its calls and changes its answer; one call, and the loopback's listener
  gets nothing.
- What would fail: a `dial` that resolved the name again would ask twice and connect to the
  listener.

### 5. The loopback and the private ranges, by address

- Try: the addresses themselves, under `any computer`: `10.0.0.1`, `192.168.1.1`,
  `169.254.169.254`, `fd00::1`, `fe80::1`, `::ffff:10.0.0.1`, `64:ff9b::a00:1`.
- Defence: an address goes through `vetted` as a name's addresses do. Only a rule that writes
  the address (`on 192.168.1.20`), or says `, private addresses too`, reaches a private one; none
  reaches this computer.
- Tests: `reach::tests::each_address_has_its_class`,
  `reach::tests::an_address_the_idea_writes_is_reached_as_written`, and the two addresses at the
  end of `open::tests::a_name_that_resolves_to_this_computer_or_a_private_network_is_not_reached`.
- Open: `any subdomain of` takes any name of two labels or more, so `any subdomain of co.uk`
  parses. lengua has no list of public suffixes; the user sees the line.

### 6. Connections held past a limit

- Try: open connections in a loop and keep them; open one to a server and never send, while
  the program computes with no call of the host.
- Defence: `room` counts the descriptors the program opened itself, at most 64 (`MFILE`). Each
  connection has a watch (`open::watch`): a thread of lengua's looks every 250 ms and shuts
  down, both ways, a connection no byte has crossed for 300 seconds. It doesn't depend on the
  program calling anything. `tcp_open` waits 5 seconds at most, and never past the run's
  deadline.
- Tests: `open::tests::a_program_holds_at_most_so_many_connections_of_its_own`;
  `open::tests::a_connection_no_byte_crosses_is_ended` (an idle time of 600 ms: the idle
  connection's read gives the end, and one that bytes cross every 200 ms lives on).
- What would fail: without `room`, the 65th open succeeds; without the watch, the idle read
  waits for the other end until the test's deadline.
- Open: a datagram socket has no watch (it holds nothing at another computer), and counts
  toward the 64. A program may open and close connections as fast as the other end takes them:
  there is no limit on how many in all, or how many a second.

### 7. UDP used to amplify, or to reach many computers

- Try: send to 255.255.255.255 or to a multicast group; on a port any computer may send to,
  answer a small datagram with a large one, or with many, so that a sender who wrote another
  computer's address makes lengua's program flood that computer; send to an address that never
  sent.
- Defence: `vetted` refuses multicast, broadcast and reserved addresses whatever the grant. A
  socket `udp_open` gives is connected to one address, and the system gives it only that
  address's datagrams. On the port the idea receives on, `udp_send_to` takes only an address
  that sent something; where the line says `for any computer`, at most three times the bytes
  that address sent (`REPLY_FACTOR`, QUIC's bound for an address not yet validated). A program
  has no raw socket, so it can't write another computer's address on what it sends.
- Tests: `open::tests::datagrams_go_only_where_the_idea_grants`;
  `open::tests::a_program_answers_only_its_senders_and_not_with_much_more`.
- Open: the three-times bound is per address for the whole run, and lengua remembers 1,024
  senders; a server that must answer with more than three times a request (a DNS server's large
  answers) can't on a port any computer reaches.

### 8. A secret told by which computers a program reaches, how many, or when

- Try: put a secret in a computer's name (it goes to the resolver, in clear); choose the port,
  or whether to connect at all, by a bit of the secret; send it and read it back.
- Defence: the secret rule (`src/checker/wasm/secret.rs`). A name is a buffer the host reads
  that isn't data: a secret in it is refused. A port is an argument: refused. No branch and no
  loop's count depends on a secret, so neither does the number of connections nor their order.
  A datagram's bytes are data, as `sock_send`'s are, and once a secret is sent, what
  `udp_recv`, `udp_recv_from` and `dns_lookup` write is secret, as what `sock_recv` reads is.
- Test: `checker::wasm::tests::a_secret_never_names_a_computer_and_a_datagram_sent_makes_what_comes_back_secret`.
- Open: the time a `tcp_open` takes depends on the network and on the name, which isn't
  secret. How long a send of secret bytes takes is the system's; lengua doesn't check it.

### 9. An import the idea doesn't grant, or one that isn't lengua's

- Try: import `tcp_open` under an idea that only `connects to`; import it from
  `wasi_snapshot_preview1` or `env`; import `lengua_net_1`'s with another type.
- Defence: the checker's import rule (`src/checker/wasm/structure.rs`), and the host again at
  every call (`policy.allows`), with the grant's own check inside each function.
- Tests: `checker::wasm::tests::rule_3_takes_lenguas_own_functions_only_as_the_idea_grants_them`;
  `wasi::tests::lenguas_own_functions_are_in_their_own_module`; a host with no grant in
  `open::tests::a_program_opens_only_what_its_idea_grants`.

### 10. A test that reaches a real computer

- Try: an idea whose tests name `example.org`, so that `check` makes real connections.
- Defence: a test's run has an internet of its own (`job::Internet`): only the loopback ports
  where the test's servers listen. `Spec::new` gives every run an empty one, and only the `run`
  tool asks for the real one. A test's addresses are held to `vetted` as real ones are.
- Tests: every test of `open::tests` runs in such an internet; `examples/follow` goes from its
  idea to done on every runner with names of example.org and no network.

### 11. A program that learns which names a private network has

- Try: under `any computer`, ask for `wiki.corp.example`, `db.internal` and so on, and tell the
  names that exist inside the user's network (refused for their private addresses) from those
  that don't (no address), without ever connecting.
- Defence: a name lengua refuses by its addresses is `Refusal::Unreached`, and the program gets
  `NOENT` for it, as for a name with no address (`held_to_the_rule`, `src/wasm/host/open.rs`).
  Only the run's report, which the user reads, says which it was. An address the program wrote
  itself gets `NOTCAPABLE`: it tells the program nothing it didn't write.
- Test: the names of
  `open::tests::a_name_that_resolves_to_this_computer_or_a_private_network_is_not_reached` all
  give `NOENT`, as `nothing.example` does, and the report has each one's reason; the same in
  `open::tests::a_names_addresses_are_given_only_as_the_idea_grants`.
- Open: how long the system's resolver takes for each kind of name is the system's.

## Checked and left as it is

- The connections lengua makes before the start (`src/connect.rs`) keep their own rule: a named
  computer is never this one. They aren't held to the private ranges: the idea names each such
  computer itself.
- `over TLS` to an address checks the certificate for the address.
- The resolver is the system's. lengua checks what it returns, whatever it asked (DNS, the hosts
  file, mDNS, a VPN's names), and sets no DNS server of its own.
- A program reaches this computer only through `connects to TCP port N`, made before the start.
  There is no grant to open connections to this computer while it runs.
