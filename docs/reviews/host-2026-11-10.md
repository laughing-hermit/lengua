# Review of lengua's WebAssembly host (main at 3e08929)

Read-only review: nothing was built or run. Every statement below comes from reading the code at
main 3e08929. The sources of cap-std 4.0.3 and Wasmtime 50.0.1, and the systems' own behaviour,
were not there to read, so what depends on them is marked with how sure I am. Paths are relative
to the repository. The tests and fixes that followed are in todo.md.

Summary: the host's core is sound. I found no way for a guest to pass a path, a pointer or a
descriptor that leaves its working folder or its memory, and none to inject into the worker
protocol. The holes are around the host: which folder a run may be given, what lengua itself reads
and allocates on the guest's or a hostile folder's behalf, the "this computer" rule for hosts, and
a lock that can be rolled back.

## Findings, by severity

### 1. High: the working folder may hold lengua's own trust roots (key, compiled-code cache), or be /proc

- Place: `src/server.rs:2177-2194` (`working_folder` refuses only a relative path, a non-folder
  and `/`); used by the tool at `src/server/wat.rs:1239` and by the shell at `src/server.rs:2165`
  (default: the current folder); opened at `src/wasm/runner.rs:305-309` and `698-703`.
- Claim broken: "files beneath one working folder" holds, but DESIGN's threat model trusts the
  data folder "as the key is" (`key` at `src/lock.rs:975`, cache at `src/wasm/engine.rs:207-215`,
  loaded by Wasmtime "as it finds it"). Nothing stops the working folder from being the data
  folder, the cache folder (also `$PLUGIN_DATA/cache`), or any ancestor of them such as the home
  folder. A checked program whose idea uses files can then read `key` (and so sign any lock) and
  write machine code into `cache/`, which the next run executes natively as the user.
- Likely in practice: `cd ~ && lengua-mcp run projects/tidy` makes the home folder the working
  folder, with `.local/share/lengua/key` beneath it (hidden names and spaces pass
  `src/names.rs`).
- Linux only, in addition: `folder: /proc` passes. `/proc/<worker pid>/environ` and
  `/proc/<worker pid>/mem` list as regular files (the numeric folder, not the `self` link), so
  the program can read the worker's environment and write the worker's own memory.
- Systems: all five for the data and cache folders; /proc on Linux x86-64 and ARM64.
- How sure: high for the missing refusal (read in code). Medium-high for /proc/pid/mem being
  writable by the worker itself.
- Tests to add (each expects a refusal before anything is compiled):
  1. data folder D, a checked program P with `- Uses: files` whose `_start` does
     `path_open(3, "key", rights=FD_READ)` and writes what it reads to standard output.
     `lengua-mcp --data-dir D run P --in D` must fail with words such as "folder holds lengua's
     data folder"; today it prints the 32 key bytes.
  2. The same with `--in <parent of D>` and the path `"<name of D>/key"`.
  3. The same with `--in D/cache`, and with `PLUGIN_DATA=X` and `--in X`.
  4. The run tool with `folder` = D, an ancestor of D, and the program folder itself (decide
     whether the last is refused; a program can rewrite its own idea.md and main.wat there,
     which only invalidates its lock).
  5. Linux: `working_folder("/proc")`, `"/proc/self"`, `"/sys"` refused.

### 2. Medium: a guest can make the worker allocate far more than its declared memory through folder listings

- Place: `src/wasm/host/files.rs:207-226` (`read_folder` reads every entry, no cap),
  `305-312` (`ordered` clones the whole listing), `619-621` (each folder descriptor keeps its own
  copy, refreshed at every `fd_readdir` with cookie 0), against the 4,352 descriptors of
  `src/wasm/host/fds.rs:75`.
- Claim broken: "Memory is held to what the module declares" and the worker staying within
  bounds. Host memory is entries x name bytes x open folder descriptors.
- Case: working folder with N files. The module calls `path_open(3, ".", oflags=DIRECTORY)`
  4,340 times and `fd_readdir(fd, buf, 1, cookie=0, used)` once on each. With 200,000 entries of
  about 100 bytes (a mail folder given as `folder`), that is about 85 GB in the worker. In a test
  the 256 MiB total (4,096 a file, `limits.rs:27`) allows 65,536 entries, but the 2 s deadline
  and the relisting after every change keep it near 1 to 3 GB.
- Systems: all five. How sure: high for the allocation pattern, medium for the sizes.
- Fix direction: share one `Arc<[Entry]>` per folder between descriptors, and cap a listing's
  entries or count listings against a budget.
- Test: a folder of 20,000 files given as `folder`; the module above; expect `MFILE` or `IO`
  from `fd_readdir` past a stated budget, and the worker's peak memory under a bound.

### 3. Medium: check, the attester and run read a handed folder's files without a size cap and through links

- Place: `src/state.rs:148-155` (`std::fs::read` of idea.md and main.wat),
  `src/server.rs:2051-2057` (`read_optional`), `2072` (a part's idea),
  `src/server/wat.rs:1374-1375` (the attester, which is meant for folders from other computers),
  `src/server/wat.rs:509`, `src/graph/mod.rs:296` and `432`. `src/lock.rs:881` is capped at
  64 KiB but its `File::open` still waits on a named pipe.
- Claim broken: no stated one, but the owner's rule "no tool call past about 40 s" and the
  server staying up. A folder someone hands the user can hold:
  - `idea.md` or `main.wat` as a link to `/dev/zero`: the read grows until the server or the
    machine runs out of memory;
  - `idea.md`, `main.wat` or `lengua.lock` as a named pipe: the call never returns, on an async
    thread;
  - `idea.md` as a link to a private text file: check's problem lines quote it to the agent.
- Systems: Linux and macOS (links and pipes inside a tree need neither on Windows, where the
  size cap is still missing: a multi-gigabyte main.wat is read whole and built in the server).
- How sure: high.
- Tests: (a) Unix: folder with `idea.md -> /dev/zero`; `lengua-mcp check <folder>` must print
  "idea.md isn't a regular file" (or "is larger than N") and exit 1 within a second. (b) Unix:
  `main.wat` made with `mkfifo`; same expectation, no hang. (c) every system: an idea.md of
  64 MiB of spaces; expect a size refusal. Open with no-follow, check `is_file()`, and read
  through `take(cap)` as `lock::read` does.

### 4. Medium-low: "this computer" is recognised by spelling only, so a named or argument-named host can be the loopback

- Place: `src/idea.rs:415-441` (`host_kind`), relied on by `src/connect.rs:170-197` ("a
  connection to the computer an argument names never goes to" this computer) and by
  `host_problem` at `src/idea.rs:444`. The address is resolved later by the system
  (`src/connect.rs:211`).
- What passes as another computer and reaches 127.0.0.1:
  - `::ffff:127.0.0.1` (and `::ffff:0.0.0.0`): parsed as IPv6, whose `is_loopback` is only
    `::1`. Linux and macOS connect to the mapped address; Windows probably refuses it.
  - `2130706433`, `127.1`, `0x7f.1`, `0177.0.0.1`: not addresses to Rust's parser, valid DNS
    labels to `label_ok`, and `getaddrinfo` reads them as 127.0.0.1 (sure for glibc, likely for
    macOS and Windows).
  - any DNS name that resolves to a loopback address.
- Claim broken: the stated rule for argument-named hosts, which guards a curl-like program
  against being pointed at local services, and the idea's line saying where a program connects.
- Systems: Linux x86-64 and ARM64 high; macOS medium; Windows medium for the numeric forms, low
  for the mapped address.
- Tests: `host_kind` gives `ThisComputer` or `NotAName` for each spelling above;
  `resolved(Argument{1,..}, ["::ffff:127.0.0.1"])` is an error; and in `connect_tcp`, an address
  that resolves to loopback or unspecified for a `Reach::Host`/`Reach::Tls` is "a connection
  lengua couldn't make" (check the resolved `SocketAddr`, including `to_ipv4_mapped`).

### 5. Medium-low: an earlier lock of the user's own can be put back, and run then runs a module a proof found wrong

- Place: `src/server/wat.rs:609-623` (the only lasting record of "wrong" is the lock's own
  `[proofs]`), `src/server.rs:872-887` (the other record is this server's memory). DESIGN
  457-458: the code stamp is written before the proofs end.
- Claim broken: "A module a proof found wrong ... [is] refused". The lock written at "tests
  pass, proving" is validly signed and names the same idea and code. Whoever can write the
  folder (the agent that wrote main.wat, a `git checkout`, or the program itself when run with
  its own folder as working folder) copies that lock, waits for the proof to record `wrong`,
  and writes the copy back. `lengua-mcp run`, and the run tool in a new session, then run it.
- Systems: all five. How sure: high.
- Test: check a program whose generated test a proof finds wrong; keep the bytes of lengua.lock
  as they are when check first says proving; after check reports the wrong proof, write those
  bytes back; `lengua-mcp run <folder>` must still refuse. Fix direction: keep wrong modules by
  hash in the data folder, beside `tested/`, and have `runnable` look there.

### 6. Low: single host calls that outlast the deadline, up to the pool's 20 seconds

- `src/wasm/host/random.rs:55-62`: `random_get(0, len)` fills up to the whole memory (4 GiB if
  declared) in one system call loop with no look at the deadline.
- `src/wasm/host/mod.rs:1160-1176`: `fd_write` to a file goes through up to 1,024 buffers, each
  up to the memory's size, with no look at the deadline between them. In a run (no file limit)
  that is up to 4 TiB of writing in one call.
- `src/wasm/host/net.rs:307-311`: `sock_shutdown` over TLS may wait 2 s whatever the deadline.
- `src/wasm/runner.rs:277-286` against `169`: up to 16 connections of 5 s each are made before
  the deadline starts.
- All are ended only by the pool's kill at the job's time plus 20 s (`src/wasm/pool.rs:32`,
  `400`, `501`), so a 2 s test can hold a worker 22 s. A shell run has no kill at all, by design.
- Systems: all five. How sure: high. No test covers a host call that runs past a deadline.
- Test: Run setup, 1 s, module with `(memory 16384 16384)` calling `random_get(0, 1 GiB)` in a
  loop of one; expect `TimedOut` within about 1.2 s (chunk the fill and call `limits.check()`).
  The same shape for `fd_write` with 1,024 buffers of 64 MiB to a file in a run.

### 7. Low: the run tool's own temporary folder has no file limit

- Place: `src/server/wat.rs:1263` (`max_written: None`) and `1272-1276`
  (`max_file_size: None`), also when no `folder` is given and the files are thrown away.
- Effect: a program fills the system's temporary folder for its time plus 20 s. On Fedora /tmp
  is memory, so this is memory too. DESIGN states "no limit", so this is a design gap, not a
  broken claim.
- Test: run tool, no `folder`, module that writes 1 GiB; expect `FBIG` at the test limits.

### 8. Low: idea.md's hash leaves out `verified` and `generated` by lines, but YAML can point into them

- Place: `src/trust.rs:101-121` (lines of the two keys are dropped before hashing),
  `src/idea.rs:1378-1386` (the whole frontmatter is parsed by serde-saphyr, which resolves
  anchors and aliases).
- Case: frontmatter with `verified: &v [...]` and `parameters: *v` (or `title: *v`). The line
  `parameters: *v` is hashed; its value lives in the unhashed block, so it can change with the
  lock still matching.
- Effect: only what the frontmatter decides (title, description, parameters for the tests). The
  grants a run reads come from body lines (`src/idea.rs:1053`), which are hashed. How sure:
  medium (not run).
- Test: two ideas that differ only inside `verified:` where another key aliases it;
  `idea_hash` must differ, or `parse` must refuse an anchor in `verified`/`generated`.

### 9. Low: the run tool reports 127.0.0.1 for a server bound to every address

- Place: `src/server.rs:556` formats `127.0.0.1:{port}` while `src/server/wat.rs:1261` passes
  `serves_anywhere` to `Listener::bind` (`src/wasm/host/net.rs:360-366`, 0.0.0.0). The shell
  path says it correctly (`src/wasm/runner.rs:689-693`). The tool is also annotated
  `open_world_hint = false` (`src/server.rs:673`) though it connects out and can listen on every
  address for ten minutes.
- Test: an idea with `listens on TCP port N for any computer`; the run tool's `serving` and
  `ended` must say every address.

### 10. Low: the data folder is not made private when something else created it first

- Place: `src/lock.rs:1070-1077` (`DirBuilder` with 0700 does nothing to a folder that exists),
  `src/wasm/engine.rs:146` (Wasmtime's cache creates `<data>/cache`, and so `<data>`, with the
  umask's mode when `doctor`, `measure` or a run comes before the first record).
- Effect: DESIGN's "the folder is made readable only by the user (0700)" does not hold in that
  order. The key file itself stays 0600 (tempfile). Linux and macOS. How sure: medium.
- Test: empty data folder, `lengua-mcp --data-dir D doctor`, then a first check; expect mode
  0700 on D.

### 11. Low: nothing caps the pages a main.wat declares, and a module with no exported memory gets 4 GiB

- Place: `src/checker/wasm/structure.rs:379-414` (minimum must equal maximum, any size),
  `src/wasm/host/limits.rs:180-191` (65,536 pages when no memory is exported as `memory`; this
  second part reaches only modules that are not main.wat, such as `measure`'s).
- Effect: every test worker of a handed folder may commit 4 GiB. No test states a bound.

### 12. Notes without a concrete break

- `src/wasm/host/mod.rs:429-431`: a refused call answers `NOTCAPABLE` before any buffer is
  checked; DESIGN line 369 says "checks the memory, then the idea". Same for
  `clock_res_get` (`clock.rs:95-99`), which checks the clock's number first. Matters only if the
  prover's model assumes the trap comes first.
- `src/names.rs:51-80`: Microsoft's list also has `COM0` and `LPT0`, and `CONIN$`/`CONOUT$`;
  legacy parsing also takes `aux .txt` (space before the dot) as the device. Probably
  unreachable through cap-std's verbatim paths; untested on Windows.
- Hard links: a hard link in the working folder to a file outside it is a regular file to
  `Kind::of` (`files.rs:43-52`) and is read and written. DESIGN says "no link is followed"
  without saying this.
- `src/wasm/host/files.rs:251-257`: listings are kept until the program itself changes
  something, so a link another process plants during a long run is not seen by `find`; cap-std
  then follows it, but only beneath the folder.
- `src/server/wat.rs:691-706`: `stdin_file` is canonicalized, checked, then read by path; a
  swap between the two reads outside `folder`. Needs another process on the machine.
- `src/graph/write.rs:119-170` with `src/graph/scan.rs:66-85`: check writes `index.md` and
  `log.md` in the program folder's parent (not root, home or temp), with titles taken from the
  handed idea, and adds entries to a `log.md` already there. Renames, so never through a link.
- Stale comments: `src/idea.rs:298-303` and `src/connect.rs:19-22` give descriptors 3 and 4;
  the host uses 4 and 5 (`fds.rs:20-24`).

## Checked and found sound

- Guest memory: every access goes through `memory::range` with `checked_add` against the
  memory's length (`mod.rs:103-111`); iovecs capped at 1,024 and the table checked before use
  (`mod.rs:234-246`); `poll_oneoff` capped at 8,704 subscriptions with `checked_mul`
  (`poll.rs:118-131`). I found no arithmetic on guest values that can wrap or panic.
- Paths: `..`, `.` and empty parts are resolved in lengua, never passed to the system
  (`files.rs:180-204`); a leading `/` and climbing out give `NOTCAPABLE`; backslash, colon
  (drives, streams), controls, trailing dot or space, device names and 8.3 shapes are refused
  per name (`names.rs:86-172`); names match byte for byte against the listing and a new name
  that clashes in case or normalization is `EXIST` (`files.rs:266-297`); a link or a special
  file on the way or at the end is `ACCES` (`files.rs:278`, `426`); cap-std resolves beneath the
  folder as a second wall.
- Descriptors: fixed roles, a new one never takes a number below the first free after the
  connections (`fds.rs:74-84`), `fd_renumber`, `path_link`, `path_symlink`, `path_readlink`
  answer `NOSYS` (`mod.rs:861-906`); only descriptor 3 is a preopen (`files.rs:345-349`); a
  held file or folder can't be renamed or removed (`files.rs:230-236`, `765`).
- Network: a guest has no connect or bind; tests reach only the test's own servers
  (`testrun.rs:677-685`); TLS checks the name against Mozilla's roots with no way to turn it
  off (`connect.rs:90-112`, `127-135`); at most 16 connections (`connect.rs:25`).
- Environment and arguments: empty unless the idea uses the environment (`mod.rs:376-382`), and
  run refuses `env` otherwise (`server/wat.rs:632-637`); the shell passes only `--env`.
- Clock: both rounded down to a microsecond (`clock.rs:75`); file times are zero
  (`files.rs:557-561`).
- Output, files, descriptors, table, stack, epochs: `stdio.rs:143-150`, `limits.rs:121-159`,
  `fds.rs:75`, `limits.rs:166-175`, `engine.rs:136`, `runner.rs:177-188`.
- Lock and run: 64 KiB cap, HMAC before parsing, constant-time compare, no key means no trust
  (`lock.rs:879-900`, `181-191`, `1039-1045`); idea.md and main.wat are read once and the same
  bytes are hashed, built and run (`state.rs:148-166`, `server/wat.rs:648-657`); the kept module
  and the worker's module file are hashed before use (`server/wat.rs:679-680`,
  `worker.rs:64-72`); lock and idea.md are written by rename (`lock.rs:911-918`,
  `server/wat.rs:426-437`).
- Tests' file names can't leave the fresh folder (`testfile.rs:573-600`), and names are not
  templates (`testfile.rs:361-366`).
- Worker protocol: guest output travels as hex inside JSON, messages are capped at 64 MiB, and
  events of another job's number are dropped (`job.rs:217`, `pool.rs:152-173`). A guest has no
  way to write the worker's real standard output.

## DESIGN.md claims the code doesn't keep, or that have no test

- "checks the memory, then the idea" (line 369): the idea is checked first (finding 12).
- "the folder is made readable only by the user (0700)" (line 465): not when it exists
  (finding 10).
- "a module a proof found wrong ... refused" (line 653): not after a rollback (finding 5).
- "no link is followed" (line 642): true of symbolic links and junctions as listed; hard links
  are followed, unsaid.
- No test found for: the listener's bind address (loopback against every address); the
  ten-minute end of a background server; `stdin_file`; `sock_recv`'s peek and wait-all;
  a host call past a deadline; a working folder that holds the data folder; a lock rolled back;
  `host_kind` for mapped and numeric loopback spellings.

## Areas with no test at all on some system

- Windows (x86-64, ARM64): junctions and other reparse points; `COM0`, `LPT0`, `CONIN$`,
  `aux .txt`; UNC, drive-relative and `\\?\` spellings reaching the host as bytes (refused by
  the backslash and colon rules, shown only by unit tests of `names`); the symbolic-link test
  (`tests/wasm_limits.rs:506-535`) skips when the runner can't make a link.
- macOS ARM64: nothing macOS-specific (no `cfg(target_os = "macos")` in tests): case and
  normalization are covered only through lengua's own folding, not against APFS.
- All five: hard links; a rename or a planted link racing a check; a descriptor kept across a
  rename beyond the `BUSY` cases; folders with very many entries; hostile folders (links,
  pipes, huge files) given to `check`, the attester or `run`; the Wasmtime cache folder and
  `tested/` being tampered with; the worker protocol under a flood of `Waiting` events.
- `tests/wasm_red_team.rs` is all at the checker's level; no test tries the host from a module
  that passed the checker beyond `tests/wasm_limits.rs` and the 109 host cases.
