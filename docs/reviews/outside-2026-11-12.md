# Review of an outside module (W23, the part moved up)

This review was written with the code, by the author of both: it is not an independent review. It
lists what a module could try once an idea may name `main.wasm`, a module that a compiler made
from Rust, C or another language, as its program; what holds against each; and the test of each.
Paths are relative to the repository. The tests were written with the defences, so none failed
before its defence existed. To see them fail, one commit that never reaches main takes defences
out; "The tests seen failing" at the end says which commit and which run.

## What changed

Until now every module lengua ran for a user was one it built from `main.wat`, after the checker
held that text to the dialect's rules. The reviews of the host (host-2026-11-10.md) and of what a
program reaches (reach-2026-11-11.md, reach-2-2026-11-11.md) took that for granted in places: the
attacker was a `main.wat` the agent wrote, which had passed the rules.

An outside module passed none. The attacker is now any WebAssembly module: a compiler's honest
output with a bug in the program, or bytes written by hand to look like one. It is steered by
what it reads, as before. The user saw the idea's grants, as before. Two more things can be
attacked: the host, through what the rules used to refuse, and the reply, which must never say
more than "trusted, not proven".

What an outside module must not do:

1. reach anything the idea doesn't grant;
2. read or write memory that isn't its own;
3. run past the deadline, or hold more memory than the cap;
4. crash or hang lengua-mcp or lengua-run;
5. make a reply, a lock, a log or a run say more than "trusted, not proven".

## Where the host leaned on a rule

Each guarantee below was held for `main.wat` by the host or the engine and by a rule. The second
column is the rule that an outside module doesn't pass; the third is what holds the guarantee
now, by itself.

Read for this review and found to hold without a rule: the descriptors' fixed roles
(`src/wasm/host/fds.rs`), the working folder's names and links (`files.rs`, `names.rs`), the
limits on output, files and descriptors (`limits.rs`, `stdio.rs`), the caps on what one call may
make lengua hold (1,024 buffers, 8,704 subscriptions, a folder's listing), a host call's look at
the deadline as it works (`random.rs`, `poll.rs`, `start.rs`), and everything of
`open.rs`, `named.rs`, `start.rs` and `term.rs`, which take every argument from the program as
untrusted already. The host's tests ran such modules before this part: `tests/host.rs` runs 109
cases written from the function table alone, and `tests/wasm_limits.rs`, `tests/host_hard.rs`
and `tests/wasm_reach.rs` run modules that passed no rule of main.wat's,
through the pool, as a test runs them.

## The threat cases

### O1. A call the idea doesn't grant

- Try: import `path_open`, `sock_accept`, `clock_time_get`, or lengua's `tcp_open`, `file_open`,
  `program_run` or `term_raw`, under an idea that grants none, and call it.
- Holds: H1, H2.
- Tests: `the_host_refuses_at_each_call_what_the_idea_doesn_t_grant` (tests/outside.rs): a
  module that skipped `check`'s reading calls fourteen such functions, each answers 76, and
  nothing is written; the same module is refused by `outside::read`.
  `wasm::outside::tests::an_import_is_a_function_of_the_host_that_the_idea_grants`.
  `check_refuses_what_the_host_can_t_hold` through `check`.
  `a_c_program_is_refused_the_network_its_idea_doesn_t_grant`: clang's output, refused by
  `check` with no grant, and refused the connection by the host under a grant of another
  computer. `a_rust_program_reads_the_file_its_idea_names`: rustc's output finds no file when
  the idea names no files.
- What would fail: with `answer`'s refusal out, the calls answer other numbers; with the
  reading's refusal out, `check` takes the module.

### O2. Another host's function, or an import that isn't a function

- Try: import `env.system`, a WASI preview 2 function, a global, a table or a memory.
- Holds: H3.
- Tests: `wasm::outside::tests::an_import_is_a_function_of_the_host_that_the_idea_grants`;
  `check_refuses_what_the_host_can_t_hold`.

### O3. Memory without end

- Try: declare no maximum and grow; declare 4 GiB; keep a memory the host can't see by not
  exporting it, or by exporting something else as `memory`.
- Holds: H4, H5.
- Tests: `wasm::outside::tests::the_memory_is_exported_and_bounded`;
  `memory_grows_to_what_the_module_declares_and_no_further`;
  `check_refuses_what_the_host_can_t_hold`.
- What would fail: with the reading's refusals out, `check` takes a memory with no maximum, or
  one that isn't exported. The growth itself is the engine's to hold, and can't be taken out.

### O4. A buffer outside the memory

- Try: give a host call an address past the memory's end, a length that reaches past it, an
  address near 2^32 whose end wraps, or a small buffer for `args_get`, whose size the program
  never asked.
- Holds: H6.
- Tests: `a_buffer_outside_the_memory_stops_the_program`: eight calls, each stopped as a load
  outside the memory is. Before this part: `tests/host.rs`'s cases and
  `a_call_takes_only_as_many_subscriptions_and_buffers_as_a_system_would`
  (tests/wasm_limits.rs).
- What would fail: with the bound out of `memory::range`, the worker's own slice check panics,
  the worker ends, and the run is lost rather than stopped as a trap.

### O5. A loop without end, calls without end

- Try: loop for ever without calling the host, in `_start` or in a start function; recurse
  without end.
- Holds: H7, H8.
- Tests: `a_loop_that_never_calls_the_host_ends_at_the_deadline`, in a test's configuration and
  in the `run` tool's, for `_start` and for a start function;
  `the_run_tool_stops_a_module_that_never_ends`, through `check` and `run`, with the server
  answering the next call; `calls_without_end_trap_and_the_worker_goes_on`.
- What would fail: with the epoch's deadline out, the loop runs until the pool gives up on the
  worker, and the run's end is no longer "timed out".
- Not held, by design: a run from a shell has no deadline. The reply's `outside` and
  docs/run.md say so.

### O6. What main.wat can't even write

- Try: call through a table's empty entry, an entry of another type or one past its end; fill or
  copy across the memory's end with bulk memory; use threads, a tail call, an exception, a
  second memory, a 64-bit memory, relaxed SIMD or a component.
- Holds: H9, H10.
- Tests: `a_call_through_a_table_is_checked_by_the_engine`;
  `bulk_memory_stays_inside_the_memory`;
  `wasm::outside::tests::what_the_engine_doesn_t_take_is_refused`;
  `wasm::engine::tests::the_engine_and_the_validator_take_the_same_features` and
  `a_table_holds_no_more_entries_than_lengua_allows`, from before this part.

### O7. A trap, to take the worker or the server with it

- Try: `unreachable`, a division by zero, a load outside the memory, a stack overflow, in a test
  and in a run.
- Holds: the engine turns each into a trap of the one store; a worker is a child process.
- Tests: `calls_without_end_trap_and_the_worker_goes_on`: four traps, and the same pool then
  runs a program.

### O8. A reply that says more than "trusted, not proven"

- Try: print "done", "proven" and "attested"; print `lengua: assertion 1 failed` and exit 134;
  pass every test.
- Holds: nothing a reply says of the module's standing comes from the module. The state, the
  `outside` lines, the lock's stamp and the log's entry come from the idea's `- Module:` line,
  which is in the text the lock's hash covers. `check` never starts a proof for it, never
  writes lengua's entry in `verified`, and the attester stops at the line.
- Tests: `an_outside_module_is_trusted_not_proven_wherever_it_is_named`: the state, the lines,
  no `memory`, proofs that say `not proven`, idea.md left as it was, the lock's text, the
  bundle's log, the `run` tool's reply, `lengua-mcp run`'s and lengua-run's first line on
  standard error, and the attester's `not attested`.
  `a_module_that_says_it_is_proven_is_trusted_not_proven`.
- What would fail: with the state `done`, both.

### O9. One kind of code checked, the other run

- Try: have `check` take `main.wasm` to trusted, then put another module in its place; or have
  it take the folder as an outside module and then run it as a program of main.wat's, to gain
  the word "done"; or the other way round, to run an unchecked module under a lock that names a
  checked main.wat.
- Holds: which file is the program comes from the idea's own lines, which the lock's hash
  covers (`Snapshot::outside`); the stamp's hash is of that file; a run refuses a folder whose
  idea, bytes and stamp don't say the same kind (`runnable`), and holds the bytes to the stamp's
  hash (`outside::as_tested`).
- Tests: `only_the_module_check_tested_runs`;
  `state::tests::an_outside_module_s_idea_makes_main_wasm_the_code`;
  `idea::tests::an_outside_module_s_idea_is_held_to_its_form`.

### O10. The idea's own words

- Try: claim in the `- Module:` line that the module was built from audited Rust.
- Holds: nothing can. lengua can't tell what a module was built from, so every place that shows
  the words says they are the idea's, and that lengua can't check them.
- Tests: `wasm::outside::tests::the_words_say_trusted_not_proven_first`.

### O11. A secret, and a part

- Try: name a secret in an outside module's idea, to have the reply say the secret rule holds;
  build on a part.
- Holds: H12, H15.
- Tests: `idea::tests::an_outside_module_s_idea_is_held_to_its_form`;
  `check_refuses_what_the_host_can_t_hold`.

### O12. A module that costs too much to read or compile

- Try: a module of gigabytes; a module made to take the compiler minutes.
- Holds: `check` reads at most 32 MiB of any file of a folder and takes at most 16 MiB of
  module; the validator's own limits on a function's size and locals; the tests' workers
  compile, in child processes, and the pool gives up on a worker 20 seconds past a test's time.
- Tests: `wasm::outside::tests::what_the_engine_doesn_t_take_is_refused` for the size alone.
- Not tested: a module made to compile slowly. The server then compiles the module once more
  itself, for a shell's runs, only after the workers compiled it within that time.

## What an outside module is refused, and what is left open

Refused, each with what to build differently: more than 16 MiB; a feature the engine has off; an
import that isn't one of the host's functions with its type; a function of lengua's own modules
without the grant; a memory not exported as `memory`, with no maximum, or of more than 1 GiB; no
`_start`; `main.wat` beside it; an idea with a `- Secret:` line; an idea with a `- Builds on:`
line.

Left open:

- **A run from a shell never stops an outside module**, as it never stops any program. For
  main.wat the rules bound every loop; for an outside module nothing does.
- **What the module was built from** is the idea's word.
- **Inside its own memory** the module is held to nothing.
- **A WASI function the idea doesn't grant links.** It must: a C or Rust standard library
  imports several at startup. The host's check at each call is then the one wall, where
  main.wat has the checker's too.
- **A module that is slow to compile** fails its tests after a test's time and 20 seconds; no
  test makes one.
- **The engine is trusted**, as before: Wasmtime's validator, compiler and runtime now see
  modules the dialect would have refused (tables, reference types, `memory.grow`, a start
  function, larger functions), all inside the features the bench's C, C++ and Rust modules
  already use.
- **No OS sandbox** wraps a worker or lengua-run, as before.
